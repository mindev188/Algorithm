# 적응형 코딩테스트 학습 자동화 Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Java 백엔드 이직 준비를 위해 8주 동안 주 6회 적응형 문제를 제공하고, 사용자가 플랫폼 통과 후 `완료`라고 보내면 검증·학습 기록·Git 커밋·GitHub push까지 자동 처리한다.

**Architecture:** 오전 문제 선정 작업, 오후 미완료 리마인더, 대화형 완료 처리기를 분리한다. 예약 작업은 로컬 상태 파일을 통해 서로 연결하고, 완료된 학습 이력만 Git 저장소에 남긴다. 기존 BaekjoonHub 구조와 커밋을 보존하며, 자동 커밋은 문제 관련 경로만 명시적으로 stage한다.

**Tech Stack:** Java, Git/GitHub, Hermes cron, Python 상태 관리 스크립트, Telegram `코딩테스트` 그룹

## 2. 수치 목표

- 총 학습 세션: 48회 (`8주 × 주 6회`)
- 공개 플랫폼 문제: 약 38회
- Hermes 창작 변형 문제: 약 10회
- 1일 기본 문제 수: 1개
- 기본 풀이 제한시간: 45~60분
- 주말 1회는 주간 상태에 따라 `복습`, `취약 유형 보강`, `미니 실전` 중 자동 선택

48회를 채우는 것보다 목표 수준 달성을 우선한다. 빠르게 성장하면 Lv.3 입문 문제 비율을 올리고, 연속 실패하면 같은 유형의 하위 문제로 되돌아간다.

## 3. 8주 커리큘럼

### 1주차 — 진단 및 기본 구현 안정화

- 배열, 문자열, 해시, 정렬
- Lv.1 상위~Lv.2 하위
- Java 컬렉션 선택, Comparator, 문자열 파싱 실수 점검
- 첫 6회 결과로 이후 난이도와 플랫폼 비율 재계산

### 2주차 — 스택·큐·완전탐색

- Stack/Deque/Queue, 시뮬레이션, 조합·순열 기초
- 익숙한 유형은 유형명 없이 출제
- 구현 실수가 반복되면 난이도 상승보다 체크리스트 보강

### 3주차 — DFS·BFS·그래프

- 격자 탐색, 최단거리, 연결 요소, 방문 처리
- 최근 풀이한 타겟 넘버·네트워크·게임 맵 최단거리와 겹치지 않는 변형 우선
- 재귀 깊이와 반복 탐색 선택 기준 학습

### 4주차 — 이분탐색·투 포인터·슬라이딩 윈도우

- 제한 조건으로 시간복잡도를 먼저 결정하는 연습
- 매개변수 탐색과 구간 문제를 구분

### 5주차 — 그리디·우선순위 큐

- 정렬 기준과 선택 근거 설명
- 정답 여부뿐 아니라 “왜 이 선택이 안전한가”를 리뷰에 포함

### 6주차 — DP 기본

- 상태 정의, 점화식, 초기값, 순회 순서
- 1차원/2차원 DP와 기초 배낭·LIS
- 실패한 문제는 해설 확인 후 다음 날 빈 코드 재구현

### 7주차 — Lv.2 상위 혼합 실전

- 유형명 비공개
- 60분 제한
- 주간 최소 1회는 2문제 미니 실전으로 대체 가능
- 정답률, 풀이 시간, 설명 가능 여부를 함께 평가

### 8주차 — Lv.3 입문 및 최종 진단

- Lv.3 입문 또는 백준 Gold 하위 문제
- 취약 유형 재시험
- 최종 모의 테스트와 다음 4주 유지 계획 생성

## 4. 적응형 난이도 규칙

학습 상태는 문제별로 다음 값을 기록한다.

- `result`: solved / failed / skipped
- `elapsed_minutes`
- `hint_level`: 0~3
- `attempt_count`
- `explanation_score`: 0~2
- `implementation_mistakes`
- `algorithm_tags`
- `review_due_dates`

난이도 조절:

1. 2회 연속 30분 이내, 무힌트 해결 → 같은 유형 난이도 상승 또는 새 유형 진입
2. 2회 연속 60분 초과 또는 실패 → 같은 유형 한 단계 하향
3. 정답이지만 설명 점수가 낮음 → 유사 강화 문제 1회
4. 동일 구현 실수 2회 → 새 문제 대신 짧은 재구현 문제
5. 7일 내 같은 유형 정답률이 70% 미만 → 플랫폼보다 해당 유형 보강 우선
6. Lv.2 상위 혼합 문제를 3회 연속 제한시간 내 해결 → Lv.3 입문 배정

## 5. 적응형 힌트 규칙

### 익숙한 유형

- 시작 시 유형명을 숨길 수 있다.
- 25~30분: 방향 힌트 1
- 40~45분: 핵심 자료구조 또는 상태 정의 힌트
- 60분: 해설 제공 여부를 확인하고, 정답 코드는 바로 노출하지 않는다.

### 새 유형

- 시작 전에 3~5분 개념 요약을 제공한다.
- 15~20분: 방향 힌트
- 35~40분: 의사코드 수준 힌트
- 60분: 해설 학습 후 빈 코드 재구현 과제로 전환한다.

### 창작 변형 문제 예외

창작 문제에는 플랫폼 정답 판정이 없으므로 `로컬 공개 테스트 통과 + 사용자 완료 선언`을 완료 조건으로 사용한다. 가능하면 숨은 경계값 테스트를 Hermes가 추가한다.

## 6. 문제 제공 형식

오전 8시 메시지는 정답을 노출하지 않고 아래 정보만 제공한다.

```text
오늘의 코테 Next Step

- 문제: 플랫폼 / 번호 / 제목
- 링크: URL
- 오늘 목표: 신규 학습 / 강화 / 복습 / 실전
- 예상 난이도: 프로그래머스 레벨 + 백준 환산 범위
- 권장 제한시간: 45~60분
- 선정 이유: 현재 취약점 또는 진도와 연결
- 시작 전 개념: 새 유형일 때만 짧게 제공
- 1차 힌트 해금 시점:
- 완료 방법: 플랫폼 통과 후 `완료`
```

문제 선정 작업은 중복 방지를 위해 기존 저장소 풀이 경로, Git 이력, 완료 이력, 현재 복습 일정을 모두 확인한다.

## 7. 완료 후 자동 처리 흐름

사용자가 코딩테스트 그룹에서 `완료`라고 보내면 다음 순서로 실행한다.

1. `.study/current.json`에서 오늘 문제를 식별한다.
2. 플랫폼 문제는 사용자의 정답 통과 선언을 완료 증거로 기록한다.
3. Git branch, remote, status를 확인한다.
4. 기존 BaekjoonHub가 만든 커밋·파일이 있는지 먼저 확인한다.
5. 최신 원격 변경을 안전하게 반영한다. 작업 트리가 더러우면 무조건 pull하지 않는다.
6. Java 코드를 컴파일하고 가능한 테스트를 실행한다.
7. 정답성, 경계값, 시간복잡도, 구현 위험을 리뷰한다.
8. 문제 README를 적응형 깊이로 작성 또는 보강한다.
9. `roadmap/review-log.md`와 구조화된 진도 이력을 갱신한다.
10. 문제 코드, 해당 README, 해당 학습 로그 경로만 명시적으로 stage한다.
11. 커밋 후 GitHub `origin/main`에 push한다.
12. 커밋 SHA와 GitHub 링크를 사용자에게 답장한다.
13. 오늘 상태를 완료로 바꿔 오후 8시 리마인드를 억제한다.

안전 규칙:

- `git add .`를 사용하지 않는다.
- `.idea/`, `out/`, `*.iml`을 커밋하지 않는다.
- 사용자가 수정 중인 템플릿이나 다른 문제 파일을 자동 stage하지 않는다.
- 강제 push, reset --hard, 사용자 변경 삭제를 금지한다.
- 컴파일 실패나 push 실패 시 완료 처리하지 않고 원인을 알려준다.
- 기존 BaekjoonHub 커밋이 이미 push된 경우 중복 `solve` 커밋을 만들지 않는다. README·복습 기록 보강만 별도 커밋한다.

## 8. 커밋 정책

기본 커밋:

```text
solve: programmers 1844 게임 맵 최단거리
solve: baekjoon 1260 DFS와 BFS
study: review graph traversal mistakes
refactor: programmers 1844 simplify bfs traversal
fix: baekjoon 1260 handle disconnected graph
```

하나의 완료 흐름에서 기본적으로 커밋 1개만 생성한다.

- 최초 정답: `solve:`
- BaekjoonHub가 이미 정답 커밋 생성: `study:` 또는 `docs:` 성격의 기록 보강
- 오답 수정: `fix:`
- 나중에 더 나은 풀이로 개선: `refactor:` 별도 커밋

기존 `프로그래머스/`, `백준/` 디렉터리는 이동하거나 이름을 바꾸지 않는다.

```text
Algorithm/

  .study/                            # 실행 중 상태, Git 비추적

    review-log.md                    # 사람이 읽는 복습 로그
```

## 10. 예약 작업 설계

### 오전 문제 선정 작업

기존 `daily-coding-test-next-step` 작업을 새로 중복 생성하지 않고 업데이트한다.

- 일정: `0 8 * * 1-6`
- 목적: 평일 5일 + 주말 하루 운영을 맞추기 위해 기본적으로 월~토 발송
- 일요일: 휴식 또는 사용자가 토요일을 쉬었을 때 보충 가능하도록 상태 기반 확장 검토
- 스킬: `coding-test-study-workflow`
- 작업 디렉터리: `/Users/kimmin/workspace/Algorithm`
- 도구: web, terminal, file
- 전달: Telegram `코딩테스트` 그룹의 명시적 채널 ID로 고정

요일 선택을 완전히 유동적으로 만들려면 매일 실행하되 주간 완료 횟수와 주말 선택 상태에 따라 `[SILENT]` 처리하는 방식이 더 정확하다. 구현 시 이 방식을 우선한다.

### 오후 미완료 리마인더

- 일정: `0 20 * * *`
- 스크립트: `scripts/coding_test_reminder.py`
- 모드: `no_agent: true`
- 동작: 오늘 문제 상태가 pending일 때만 짧은 메시지 출력
- 완료/휴식/미출제 상태면 stdout을 비워 발송하지 않음
- 전달: Telegram `코딩테스트` 그룹의 명시적 채널 ID로 고정

리마인드 예시:

```text
오늘 코테 문제가 아직 미완료예요.

- 남은 목표: 45~60분 1문제
- 막혔다면: `힌트`
- 플랫폼 통과 후: `완료`
- 오늘 쉬려면: `휴식`
```

## 11. 사용자 명령 규약

코딩테스트 그룹에서는 아래 짧은 명령으로 상태를 바꾼다.

- `완료` — 검증·리뷰·커밋·push 시작
- `힌트` — 현재 경과시간과 이력에 맞는 다음 힌트 제공
- `실패` — 막힌 지점 기록 후 해설/재구현 흐름 시작
- `휴식` — 오늘 리마인드 중단, 주간 6회 계산에 반영
- `이월` — 다음 학습일에 같은 문제 유지
- `교체` — 문제 적합성을 기록하고 대체 문제 1개 선정
- `복습` — 현재 복습 예정 문제 제시
- `현황` — 이번 주 완료 횟수, 정답률, 취약 유형, 목표까지 거리 표시

## 12. 성공 기준

기능 성공 기준:

- 오전 8시 문제는 하루 최대 1개만 발송된다.
- 오후 8시 리마인드는 미완료일 때만 발송된다.
- 이미 푼 문제를 다시 추천하지 않는다. 의도적 복습은 예외다.
- `완료` 후 대상 Java 코드가 검증된다.
- 다른 작업 파일을 섞지 않고 커밋한다.
- push 성공 후 SHA와 링크가 답장에 포함된다.
- BaekjoonHub 커밋과 중복 커밋하지 않는다.

학습 성공 기준:

- Lv.2 상위 혼합 문제를 유형 힌트 없이 제한시간 내 안정적으로 해결한다.

## 14. 게임형 성장 시스템

### 14.1 표시할 성장 지표

사용자에게는 서로 역할이 다른 두 점수를 함께 보여준다.

- `XP`: 학습 행동의 누적 경험치. 실패하거나 쉬어도 절대 감소하지 않는다.
- `SR`: 현재 코딩테스트 수행 능력을 나타내는 0~1000 실력 점수. 최근 성과에 따라 오르내린다.

표시 예시:

```text
PLATINUM IV · 프로그래머스 Lv.2 상위
SR 628 ▲12
XP 3,460 / 다음 레벨까지 140
주간 4/6 · 스트릭 5일
```

### 14.2 혼합 티어

첫 6문제는 배치 기간이며 `UNRANKED`로 표시한다. 배치가 끝나면 실제 결과를 기준으로 시작 SR을 정한다.

| SR | 게임 티어 | 실제 코테 수준 표시 |
|---:|---|---|
| 0~299 | BRONZE | 프로그래머스 Lv.1 학습 |
| 300~449 | SILVER | Lv.1 안정 / Lv.2 입문 |
| 450~599 | GOLD | Lv.2 기본 |
| 600~749 | PLATINUM | Lv.2 상위 |
| 750~879 | DIAMOND | Lv.3 입문 |
| 880~1000 | MASTER | Lv.3 안정 |

각 티어는 IV → III → II → I 네 구간으로 나누어 승급 경험을 자주 제공한다. 실제 채용 경쟁력은 게임 티어만으로 단정하지 않고, 항상 `실제 코테 수준 표시`를 함께 보여준다.

### 14.3 XP 규칙

기본 XP:

- 문제에 성실히 도전: +20 XP
- 프로그래머스 Lv.1 또는 백준 Bronze/Silver 하위 해결: +60 XP
- 프로그래머스 Lv.2 또는 백준 Silver 상위/Gold 하위 해결: +100 XP
- 프로그래머스 Lv.3 또는 백준 Gold 문제 해결: +160 XP

보너스 XP:

- 무힌트 해결: +30 XP
- 제한시간 내 해결: +20 XP
- 복잡도·반례 설명 완료: +20 XP
- 실패 문제 재도전 성공: +50 XP
- 예정된 복습 성공: +40 XP
- 주간 6회 완료: +100 XP
- 새 알고리즘 유형 첫 정복: +50 XP

XP 안전 규칙:

- 실패: 획득한 도전 XP를 유지한다.
- 계획된 휴식: 변화 없음.
- 미완료·이월: 감점 없음.
- 힌트 사용: 보너스가 줄 수는 있지만 기존 XP는 감소하지 않는다.

### 14.4 SR 규칙

SR은 문제 난이도 대비 실제 수행 결과를 반영한다.

- 적정 난이도 무힌트·제한시간 내 해결: +12~18
- 적정 난이도 힌트 사용 후 해결: +5~10
- 상위 난이도 해결: +18~25
- 설명 또는 구현 품질이 부족한 정답: +2~6
- 충분히 시도했지만 실패: -4~-8
- 연속 실패: 하루 최대 하락 폭 -12
- 실패 문제 재풀이 성공: 기존 하락분 회복 + 추가 보너스
- 계획된 휴식·이월: SR 변화 없음

SR 하락은 벌점이 아니라 현재 추천 난이도를 맞추기 위한 보정값으로 설명한다. 사용자가 실패했을 때는 하락 숫자보다 `회복 퀘스트`와 회복 가능한 점수를 먼저 보여준다.

### 14.5 스트릭

- 주 6회 목표에 맞춰 계획된 휴식 1일은 스트릭을 끊지 않는다.
- `휴식` 명령으로 등록한 날도 보호한다.
- 문제를 해결하지 못해도 30분 이상 성실히 시도하고 `실패` 기록을 남기면 학습 스트릭은 유지한다.
- 단순 미응답은 스트릭 보호 대상이 아니지만 XP와 SR을 차감하지 않는다.

스트릭 보상:

- 3일: `시동 완료` 배지 + 30 XP
- 7일: `루틴 빌더` 배지 + 70 XP
- 14일: `알고리즘 탐험가` 배지 + 150 XP
- 30일: `꾸준함의 증명` 배지 + 300 XP

### 14.6 알고리즘 배지

각 유형은 `발견 → 숙련 → 정복` 세 단계로 표시한다.

- 해시 수집가
- 스택 가디언
- 큐 러너
- 완전탐색 탐험가
- 그래프 워커
- BFS 패스파인더
- DFS 딥다이버
- 이분탐색 스나이퍼
- 투 포인터 듀얼리스트
- 그리디 전략가
- 힙 마스터
- DP 연금술사

기본 해금 기준:

- 발견: 해당 유형 첫 문제 완료
- 숙련: 최근 3문제 중 2문제 제한시간 내 해결
- 정복: 유형 비공개 상태에서 상위 난이도 문제 해결 및 설명 완료

### 14.7 주간 퀘스트

매주 월요일 현재 약점을 기준으로 3개만 생성한다.


모든 퀘스트 완료 시 `PERFECT WEEK` 배지와 +150 XP를 지급한다. 퀘스트를 완료하지 못해도 감점하지 않고 다음 주 범위를 줄여 다시 제안한다.

### 14.8 메시지 표시 방식

오전 문제 메시지 상단:

```text
[PLATINUM IV] SR 628 · XP 3,460

```

문제 완료 메시지:

```text
╔════════ QUEST CLEAR ════════╗
  프로그래머스 Lv.2 해결
  +150 XP · SR +12
  스트릭 6일
  새 배지: BFS 패스파인더
╚═════════════════════════════╝

PLATINUM IV → PLATINUM III
다음 승급까지 SR 38
```

주간 상세 리포트:

- 이번 주 XP와 SR 변화
- 해결/실패/재풀이 수
- 평균 풀이 시간과 힌트 사용률
- 새로 획득한 배지
- 유형별 숙련도
- 다음 주 보스 유형 1개
- 다음 티어까지 필요한 구체적 행동

## 15. 현재 발견된 선행 위험

- 현재 작업 트리에 `templates/JavaMainTemplate.java`, `templates/Solution.java` 변경과 IntelliJ 산출물이 존재한다.
- 기존 README의 권장 `problems/` 구조와 실제 BaekjoonHub의 `프로그래머스/`, `백준/` 구조가 다르다.
- 기존 오전 작업은 매일 실행되며 아직 개인 선택값이 반영되지 않았다.
- 기존 오전 작업의 전달 대상이 `origin`이므로, 장기 안정성을 위해 코딩테스트 그룹의 명시적 chat_id 고정이 필요하다.
- 사용자의 `완료` 선언은 플랫폼 통과 증거이지만 자동 브라우저 제출 검증은 하지 않는다.

위 위험은 구현 시 먼저 보호 장치를 만든 뒤 자동 커밋을 활성화하는 순서로 해결한다.
